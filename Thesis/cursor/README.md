# MockControl

Система централизованного управления и мониторинга заглушек (Java .jar/.war): жизненный цикл процессов, HTTP-прокси, rate limiting, метрики Prometheus. Подробное описание — в [.cursor/rules/cursor_prompt.md](.cursor/rules/cursor_prompt.md).

## Требования

| Компонент | Версия / примечание |
|-----------|---------------------|
| **Python** | 3.10+ |
| **Redis** | Сервер с включённым режимом персистентности (в ТЗ рекомендуется AOF `appendfsync everysec`) |
| **Java** | 17+ на **целевых хостах**, где выполняются заглушки (локально или по SSH) |

На машине с MockControl должен быть доступен `redis` по URL из настройки `REDIS_URL`. Для удалённых хостов нужен SSH-доступ и корректные пути к `java` и рабочему каталогу.

## Установка

Из корня проекта (каталог с `main.py` и `requirements.txt`):

```bash
pip install -r requirements.txt
```

Рекомендуется виртуальное окружение (`python -m venv .venv` и активация).

## Настройка

1. Скопируйте пример окружения и отредактируйте при необходимости:

   ```bash
   cp .env.example .env
   ```

2. Основные переменные (полный список — в `.env.example` и в `config.py`):

   - `REDIS_URL` — подключение к Redis.
   - `FERNET_KEY_PATH` — файл ключа Fernet для паролей SSH; при отсутствии файла ключ будет создан (каталоги создаются автоматически; на Unix желательны права **600** на файл ключа).
   - `TEMP_UPLOAD_DIR` — каталог временных загрузок артефактов.

На Linux для продакшена типичны пути вроде `/etc/mockcontrol/fernet.key` и `/tmp/mockcontrol`; на других ОС задайте подходящие пути в `.env`.

## Запуск Redis

Redis должен быть запущен **до** старта MockControl.

**Ubuntu / Astra Linux и аналоги** (пакет `redis-server`):

```bash
sudo systemctl enable --now redis-server
```

Проверка:

```bash
redis-cli ping
```

Должен ответить `PONG`.

## Запуск приложения

Из каталога с `main.py`:

```bash
python main.py
```

Либо явно через ASGI-сервер:

```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```

По умолчанию `main.py` поднимает сервис на порту **8000**.

## Веб-интерфейс

Откройте в браузере: [http://localhost:8000](http://localhost:8000) — главная панель (dashboard).

- Настройки: [http://localhost:8000/settings](http://localhost:8000/settings)
- Журналы: [http://localhost:8000/logs](http://localhost:8000/logs)

Метрики Prometheus: `GET http://localhost:8000/metrics`

## Первоначальная настройка

Рекомендуемый порядок в UI **Настройки** (`/settings`):

1. **Учётная запись SSH** — логин и пароль (пароль шифруется и хранится в Redis).
2. **Хост** — hostname/IP, SSH-порт, привязка к учётной записи, рабочий каталог, путь к Java, диапазон портов для заглушек.
3. **Заглушка** — регистрация артефакта (.jar/.war) на выбранном хосте и при необходимости запуск.

Без настроенного хоста и учётной записи удалённые операции по SSH недоступны; для **локального** хоста (когда система определяет машину как локальную) используются прямые вызовы ОС без SSH.
