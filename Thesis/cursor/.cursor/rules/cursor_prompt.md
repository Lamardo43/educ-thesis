# MockControl — Полное техническое задание для разработки

## Цель проекта

Разработать **MockControl** — автоматизированную информационную систему для централизованного управления и мониторинга состояния распределённой инфраструктуры имитационных сервисов (заглушек) в среде нагрузочного тестирования. Система управляет жизненным циклом Java-приложений (.jar/.war), проксирует к ним HTTP-трафик, ограничивает интенсивность запросов (Rate Limiting) и экспортирует метрики в Prometheus.

---

## Стек технологий

- **Язык**: Python 3.10+ (asyncio, async/await повсеместно)
- **Фреймворк**: FastAPI + Uvicorn (ASGI)
- **СУБД**: Redis (режим AOF `appendfsync everysec`)
- **SSH/SCP**: asyncssh (асинхронная библиотека)
- **HTTP-клиент для прокси**: httpx (AsyncClient с connection pooling)
- **Шаблонизатор**: Jinja2 (Server-Side Rendering)
- **Шифрование паролей**: cryptography (Fernet / AES-128-CBC)
- **Валидация**: Pydantic v2
- **Целевая ОС**: Linux (Astra Linux / Ubuntu)

Файл зависимостей `requirements.txt` составить самостоятельно на основании фактически импортируемых библиотек.

## Хранение данных в Redis

### КРИТИЧЕСКИ ВАЖНО: Redis Hash вместо JSON-строк

Каждый объект (заглушка, хост, учётная запись) хранится как **Redis Hash** (HSET/HGET/HGETALL/HDEL), а **не** как сериализованная JSON-строка. Это позволяет атомарно обновлять отдельные поля без перечитывания всего объекта и устраняет race conditions при конкурентных обновлениях.

### Структура ключей и полей

#### Заглушки: `mocks:{filename}`

Тип: **Hash**

| Поле | Тип | Описание |
|------|-----|----------|
| hostname | str | Хост, на котором размещена заглушка |
| port | int/empty | TCP-порт процесса (пусто, если не запущена) |
| pid | int/empty | PID процесса на хосте |
| status | str | `REGISTERED` / `RUNNING` / `STOPPED` / `ERROR` |
| jvm_args | str | Аргументы JVM |
| rate_limit | int | Макс. запросов в секунду |
| rate_limit_enabled | str | `"true"` / `"false"` |
| registered_at | str | ISO 8601 |
| started_at | str/empty | ISO 8601 |
| artifact_path | str | **Immutable.** Полный путь к файлу на целевом хосте, фиксируется при регистрации и никогда не пересчитывается |

Реестр: `mocks:registry` — тип **Set**, содержит filename.

#### Хосты: `hosts:{hostname}`

Тип: **Hash**

| Поле | Тип | Описание |
|------|-----|----------|
| ssh_port | int | Порт SSH (по умолчанию 22) |
| account_uuid | str | UUID учётной записи SSH |
| working_dir | str | Рабочая директория на хосте |
| java_path | str | Абсолютный путь к исполняемому файлу java |
| mock_port_min | int | Минимальный порт для заглушек |
| mock_port_max | int | Максимальный порт для заглушек |
| description | str | Описание хоста |
| status | str | `AVAILABLE` / `UNAVAILABLE` / `UNKNOWN` |
| last_checked_at | str | ISO 8601 |

Реестр: `hosts:registry` — тип **Set**.

#### Учётные записи: `accounts:{uuid}`

Тип: **Hash**

| Поле | Тип | Описание |
|------|-----|----------|
| username | str | Логин SSH |
| password_enc | str | Зашифрованный пароль (Fernet) |
| description | str | Описание |
| created_at | str | ISO 8601 |

Реестр: `accounts:registry` — тип **Set**.

#### Счётчик Rate Limiter: `rate:{filename}:{window}`

Тип: **String** (используется атомарная команда INCR).

`{window}` = целочисленное деление текущего unix timestamp на размер окна (1 секунда). TTL = 2 секунды, устанавливается командой EXPIRE только при первом запросе в окне (когда INCR возвращает 1).

#### Глобальные настройки: `settings:global`

Тип: **Hash**

| Поле | Значение по умолч. | Описание |
|------|---------------------|----------|
| rate_limit_window_size | 1 | Размер окна Rate Limiter (сек) |
| host_check_interval_sec | 30 | Интервал проверки хостов (сек) |
| proxy_timeout_sec | 10 | Таймаут проксирования (сек) |
| log_retention_lines | 1000 | Макс. строк лога в буфере |

#### Логи заглушек: `logs:{filename}`

Тип: **List** (RPUSH для добавления, LRANGE для чтения, LTRIM для ограничения размера).

#### Счётчики метрик

`metrics:proxy_total:{filename}` и `metrics:rejected_total:{filename}` — тип **String** (INCR). Инкрементируются при каждом проксированном запросе и каждом отклонении Rate Limiter соответственно.

## Механизм определения локального хоста (`core/host_resolver.py`)

Система должна уметь определять, является ли целевой хост **локальной машиной** (той же, на которой работает управляющее приложение). Это необходимо для оптимизации: при работе с локальным хостом не нужны SSH/SCP — файлы копируются напрямую через файловую систему, процессы запускаются через `asyncio.create_subprocess_exec`, проверка портов и PID выполняется локально.

Хост считается локальным, если его `hostname` равен одному из значений: `localhost`, `127.0.0.1`, `::1`, фактический hostname машины (результат `socket.gethostname()`), любой из IP-адресов сетевых интерфейсов машины.

Модуль должен предоставлять функцию `is_local(hostname: str) -> bool`, результат которой кэшируется.

## Компоненты системы — детальные спецификации

### 1. Lifecycle Manager (`services/lifecycle.py`)

Управляет жизненным циклом заглушек. Все операции с целевым хостом **ветвятся** в зависимости от того, является ли хост локальным (см. `host_resolver.is_local()`).

#### Регистрация заглушки

Входные данные: загруженный файл (.jar/.war), hostname, jvm_args, rate_limit, auto_start.

Алгоритм:
1. Проверить, что filename отсутствует в `mocks:registry` (SISMEMBER). Если есть → ошибка 409.
2. Прочитать конфигурацию хоста из Redis.
3. Вычислить `artifact_path = {working_dir}/{filename}` и сохранить его как immutable-поле записи заглушки.
4. Сохранить загруженный файл во временный каталог.
5. **В фоновой задаче** (FastAPI `BackgroundTasks`):
   - **Если хост локальный**: скопировать файл из временного каталога в `artifact_path` средствами файловой системы. Создать директорию, если не существует. Установить права 755.
   - **Если хост удалённый**: прочитать учётную запись, расшифровать пароль, скопировать файл через SCP (из SSH-пула).
   - Удалить временный файл.
   - Сохранить запись заглушки в Redis со статусом REGISTERED.
   - Добавить filename в реестр mocks:registry.
   - Если auto_start → вызвать запуск.

#### Запуск заглушки

1. Прочитать конфигурацию заглушки и хоста из Redis.
2. Проверить, что статус не RUNNING.
3. Найти свободный порт в диапазоне [mock_port_min, mock_port_max]:
   - **Локальный хост**: проверить занятость портов локально (попытка bind или чтение системной информации о занятых портах).
   - **Удалённый хост**: выполнить через SSH команду для получения списка занятых портов и выбрать первый свободный в диапазоне.
4. Запустить Java-процесс:
   - **Локальный хост**: через `asyncio.create_subprocess_exec` с перенаправлением stdout/stderr в лог-файл `/tmp/mockcontrol_{filename}.log`. Запуск в фоновом режиме. Получить PID из объекта процесса.
   - **Удалённый хост**: через SSH выполнить команду запуска Java-процесса в фоновом режиме (nohup), с JVM-аргументами и указанием порта. Получить PID из stdout.
5. Подождать 2 секунды, проверить что процесс жив.
6. Обновить Redis: port, pid, status=RUNNING, started_at.
7. Создать httpx.AsyncClient для данной заглушки в глобальном реестре клиентов (с connection pooling и keep-alive).

#### Остановка заглушки

1. Прочитать PID и hostname из Redis.
2. Послать SIGTERM:
   - **Локальный хост**: через os.kill.
   - **Удалённый хост**: через SSH.
3. Ждать до 5 секунд завершения. Если не завершился → SIGKILL.
4. Обновить Redis: status=STOPPED, очистить port, pid, started_at.
5. Закрыть httpx-клиент для данной заглушки.

#### Удаление заглушки

1. Если статус RUNNING → остановить.
2. Удалить файл артефакта:
   - **Локальный хост**: через os.remove.
   - **Удалённый хост**: через SSH.
3. Удалить запись из Redis (DEL ключа, SREM из реестра).
4. Удалить логи (DEL `logs:{filename}`).
5. Удалить счётчики Rate Limiter (SCAN по паттерну `rate:{filename}:*` → DEL).
6. Удалить счётчики метрик.

### 2. SSH Connection Pool (`core/ssh_pool.py`)

Пул постоянных (persistent) SSH-соединений. Одно соединение на хост, переиспользуемое для всех операций. При разрыве — автоматическое пересоздание при следующем вызове.

Перед повторным использованием соединения проверяется его жизнеспособность (простая команда с таймаутом). Если проверка неуспешна — соединение закрывается и создаётся заново.

Мьютекс (asyncio.Lock) на каждый хост для предотвращения одновременного создания нескольких соединений.

Методы: получить соединение, выполнить команду, загрузить файл по SCP, закрыть все соединения.

**Пул не используется для локальных хостов** — Lifecycle Manager и Health Checker работают с ним только для удалённых хостов.

---

### 3. Proxy Engine (`services/proxy.py` + `api/proxy_router.py`)

Прозрачный обратный прокси на прикладном уровне.

#### Глобальный реестр httpx-клиентов

Один `httpx.AsyncClient` на каждую запущенную заглушку с пулом соединений (connection pooling, keep-alive) и настроенным таймаутом. Клиент создаётся при запуске заглушки и закрывается при остановке. Не должно быть создания нового HTTP-соединения на каждый проксируемый запрос — это критично для производительности.

#### Маршрут прокси

Catch-all маршрут, принимающий **любой HTTP-метод** (GET, POST, PUT, DELETE, PATCH, HEAD, OPTIONS).

Формат пути: `/{mock_name}/{path:path}` **с учётом того, что path может быть пустым**. Запрос вида `GET /{mock_name}` или `GET /{mock_name}/` (без дополнительного пути) должен корректно проксироваться к корню заглушки (`http://host:port/`). Необходимо предусмотреть оба варианта маршрута: с path и без.

`mock_name` — это filename заглушки целиком (включая расширение, например `payment-service-stub.jar`).

Алгоритм обработки запроса:
1. Прочитать запись заглушки из Redis по mock_name.
2. Если заглушка не найдена → HTTP 404.
3. Если status != RUNNING → HTTP 503 (Service Unavailable).
4. Если rate_limit_enabled == true → вызвать Rate Limiter. Если лимит превышен → HTTP 429 (Too Many Requests), инкрементировать счётчик отклонённых запросов.
5. Инкрементировать счётчик проксированных запросов.
6. Получить httpx-клиент из реестра.
7. Переслать запрос заглушке: тот же HTTP-метод, все заголовки (кроме Host), тело запроса, query-параметры. URL: `http://{hostname}:{port}/{path}?{query_string}` (если path пустой → `http://{hostname}:{port}/`).
8. Вернуть ответ заглушки клиенту в неизменном виде: статус-код, заголовки, тело.

### 4. Rate Limiter (`services/rate_limiter.py`)

Алгоритм **Fixed Window Counter** с окном **1 секунда**.

Логика:
1. Вычислить метку текущего окна: целочисленное деление текущего unix-timestamp на размер окна.
2. Сформировать ключ: `rate:{filename}:{window}`.
3. Атомарно инкрементировать счётчик (Redis INCR).
4. Если INCR вернул 1 (первый запрос в окне) — установить TTL ключа равным удвоенному размеру окна (защита от утечки памяти).
5. Если значение счётчика > лимита → запрос отклонён. Иначе → разрешён.

---

### 5. Health Checker (`services/health_checker.py`)

Фоновая задача, запускаемая при старте приложения. Работает в бесконечном цикле с паузой `host_check_interval_sec` между итерациями.

#### Проверка доступности хостов

Для каждого хоста из реестра:
- **Локальный хост**: всегда AVAILABLE (опционально проверить наличие java по пути java_path).
- **Удалённый хост**: попытка выполнить простую команду через SSH (из пула). Успешно — AVAILABLE, ошибка — UNAVAILABLE.

Обновить поля status и last_checked_at в Redis.

#### HTTP Health Check заглушек

Для каждой заглушки со статусом RUNNING:
1. Проверить наличие процесса:
   - **Локальный хост**: проверка существования процесса по PID через системный вызов (без отправки сигнала).
   - **Удалённый хост**: проверка через SSH.
2. Выполнить HTTP GET к `http://{hostname}:{port}/` с таймаутом 3 секунды (отдельный httpx-клиент для health check, не из реестра прокси-клиентов).
3. Если PID не существует ИЛИ HTTP не отвечает → обновить статус на ERROR.
4. Если всё в порядке → подтвердить RUNNING.

---

### 6. Crypto Service (`core/crypto.py`)

Симметричное шифрование паролей учётных записей SSH перед сохранением в Redis и расшифровка перед использованием.

AES-128-CBC через Fernet. Ключ шифрования хранится в файле с правами 600. При первом запуске, если файл не существует, генерируется новый ключ. Расшифрованный пароль существует только в оперативной памяти на время установки SSH-соединения.

---

### 7. Metrics Exporter (`services/metrics.py`)

Эндпоинт `GET /metrics` возвращает plain text в Prometheus exposition format.

Метрики:
- `mockcontrol_mocks_total` (gauge) — общее число зарегистрированных заглушек
- `mockcontrol_mocks_running` (gauge) — число запущенных
- `mockcontrol_mocks_errors` (gauge) — число в статусе ERROR
- `mockcontrol_hosts_available` (gauge) — число доступных хостов
- `mockcontrol_proxy_requests_total{mock="..."}` (counter) — проксированные запросы по заглушке
- `mockcontrol_rate_limit_rejected_total{mock="..."}` (counter) — отклонённые запросы по заглушке

Для сбора использовать **Redis Pipeline** — прочитать все данные одним batch.

---

### 8. Log Collector (`services/log_collector.py`)

Фоновая задача. При запуске заглушки stdout/stderr перенаправляются в файл `/tmp/mockcontrol_{filename}.log` на целевом хосте.

Каждые 2 секунды для каждой заглушки со статусом RUNNING:
1. Прочитать новые строки из лог-файла:
   - **Локальный хост**: чтение файла, отслеживание позиции (seek/tell).
   - **Удалённый хост**: SSH-команда tail.
2. Добавить строки в Redis-список `logs:{filename}` (RPUSH).
3. Обрезать список до максимального размера (LTRIM).

## Запуск приложения

### Startup (lifespan)

1. Подключиться к Redis.
2. Инициализировать SSH Pool.
3. Инициализировать реестр httpx-клиентов.
4. Инициализировать CryptoService.
5. Загрузить глобальные настройки из Redis (или создать defaults).
6. **Восстановление состояния**: для каждой заглушки со статусом RUNNING проверить процесс на хосте (с учётом локальности). Если жив — подтвердить RUNNING, создать httpx-клиент. Если нет — статус STOPPED, очистить port/pid/started_at.
7. Запустить фоновые задачи: health_checker, log_collector.

### Shutdown

Закрыть все httpx-клиенты, SSH Pool, Redis.

### Порядок маршрутов

1. Web HTML (`/`, `/settings`, `/logs`)
2. API v1 (`/api/v1/...`)
3. Metrics (`/metrics`)
4. Static (`/static`)
5. **Proxy catch-all** — **ПОСЛЕДНИМ**

## Требования к качеству

1. **Полная асинхронность**: все I/O через async/await. Никаких блокирующих вызовов.
2. **Типизация**: type hints на всех функциях.
3. **Pydantic**: для всех входных/выходных данных API.
4. **Error handling**: осмысленные HTTP-коды (400, 404, 409, 500, 503) с JSON `{"detail": "..."}`.
5. **Logging**: модуль `logging`, не print.
6. **Docstrings**: на всех публичных функциях и классах.
7. **Никаких хардкодов**: всё через Settings или Redis.

---

## Критические нюансы

1. **Proxy catch-all — последним** в порядке регистрации роутеров.
2. **Пустой path**: `GET /{mock_name}` и `GET /{mock_name}/` проксируются к корню заглушки.
3. **Локальный хост**: при любой операции сначала `is_local(hostname)`. Если да — прямые системные вызовы, без SSH.
4. **Удаление хоста**: 409 если есть привязанные заглушки (с их перечислением).
5. **Удаление учётной записи**: 409 если используется хостом.
6. **Immutable artifact_path**: фиксируется при регистрации. Изменение working_dir хоста не влияет на уже зарегистрированные заглушки.
7. **Модальные окна**: чистый HTML/CSS/JS, без библиотек.
8. **JavaScript**: минимальный, только для интерактивности. Никаких фреймворков.
